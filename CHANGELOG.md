# Changelog

## [1.4.0] - 2026-09-23

### Added
- Новый режим работы антенны: **⚓ По опорным маякам** (`beacon_referenced`)
  - Позиция судна вычисляется по известным координатам одного или нескольких опорных маяков (обратная геодезическая задача)
  - Усреднение позиции через медиану (при нескольких опорных), контроль разброса и возраста
  - Буфер позиций с временем жизни 20 секунд (защита от устаревших данных)
  - DH-фильтр на позицию судна (защита от физически невозможных прыжков), один на все опорные маяки
  - Отвергнутые позиции судна отображаются на карте серым крестиком с подписью «ОТВЕРГНУТО»
  - DH-фильтр и сглаживатель для искомых маяков (в географических координатах)
- Панель **«⚓ Опорные маяки»** в меню Инструменты:
  - Добавление/удаление опорных маяков с координатами и глубиной
  - Список опорных маяков с возможностью удаления
  - Индикатор состояния (активен/готов/ожидание данных)
  - Показ текущей позиции судна (координаты, источников, разброс, возраст)
- Опция **«⚓ По опорным маякам»** в настройках режима антенны
- Новый шаг **«Опорные маяки»** в стартовом мастере настройки (UIWizard)
- Индикатор **⚓** в панели антенны при активном режиме
- Строка **«⚓ Точность»** в панели антенны — разброс между опорными маяками, количество источников, возраст (показывается только при 2+ опорных)
- Строка **«GNSS»** и **«Расхождение»** в панели антенны — сравнение позиции по опорным маякам с GNSS-позицией (при наличии GNSS-данных)
- Настройка **«Макс. скорость судна»** в ⚙ Настройки → Фильтр судна (DH) — порог DH-фильтра позиции судна (0.5–50 м/с, по умолчанию 2.0)
- Визуализация режима на карте:
  - Опорные маяки выделяются золотой обводкой и значком ⚓
  - Пунктирные золотые линии от опорных маяков до позиции судна
  - Круг разброса вокруг позиции судна
- Сохранение опорных маяков в localStorage (восстановление между сессиями)
- Автоматическая установка якоря карты (anchor) при добавлении/активации опорного маяка

### Changed
- **Рефакторинг `azm-manager.js`:** `processBeaconData()` разбит на диспетчер и стратегии (`strategyCartesianFixed`, `strategyGeographic`, `strategyBeaconReferenced`) — упрощает добавление новых режимов
- **Рефакторинг CSS:** введены переменные `--radius-*` и иерархия `--z-*`; удалены дубли; dropdown-меню и панели переведены на класс `.visible` вместо inline-стилей
- Кнопка **Лог** унифицирована по размеру с остальными кнопками top-bar
- Все панели получили единый стиль (общий padding, border-radius, box-shadow)
- Кнопки внутри панелей унифицированы через классы `.panel-btn-*`
- Индикатор прогресса воспроизведения (`#playback-progress`) и контрол скорости (`#playback-speed-control`) управляются через класс `.active`
- В режиме `beacon_referenced` GNSS-позиция сохраняется отдельно (для сравнения) и не перезаписывает рабочую позицию судна
- Опорные маяки не добавляются в трек маяка, к ним не применяются DH-фильтр и сглаживатель (координаты заданы пользователем и стабильны)
- Трек станции в режиме `beacon_referenced` строится по вычисленной позиции судна (не по GNSS)
- Документация (guide и readme) актуализирована

### Fixed
- **CSS:** исправлена опечатка `..dropdown-menu` (двойная точка) — из-за неё не работали подменю в меню Инструменты
- **CSS:** переменные `--radius-sm/--radius/--radius-lg` не были определены — теперь скругления работают корректно
- **UI:** подменю (POI, Калибровки) больше не раскрываются всегда, работают по hover и по tap
- **UI:** dropdown-меню на мобильных/планшетах больше не уезжают за край экрана
- **UI:** подменю на узких экранах раскрываются вниз (в виде «дерева»), не уезжают вбок
- **Возраст позиции судна** в панели антенны показывал миллиарды секунд (сравнение виртуального и реального времени). Добавлено поле `updatedAt` (реальное время) в `shipPosition`
- **`recalculateShipPosition`** использовал `Date.now()` вместо `timeProvider()` — в режиме воспроизведения лога это приводило к тому, что все записи буфера считались устаревшими
- **DH-фильтр позиции судна** работал в градусах вместо радиан (как `DHTrackFilter` для маяков) — из-за этого отвергались все позиции
- **Опорный маяк** не отображался по своим координатам, если не был установлен якорь карты. Anchor теперь устанавливается при добавлении/активации опорного маяка
- **Трек станции** не строился в режиме `beacon_referenced`, если опорный маяк — единственный. Точка добавляется в раннем выходе для опорного маяка

### Notes
- Режим `beacon_referenced` требует **минимум один опорный маяк** с известными координатами
- В режиме `beacon_referenced` смещения антенны (`offsetX/offsetY`) **не применяются** — только угловая поправка `phi`
- Точность позиции (`spread`) оценивается **только при 2+ опорных маяках**. При одном маяке `spread = 0` и строка «⚓ Точность» в панели антенны скрывается
- GNSS-позиция (если есть в логе) отображается в панели антенны для сравнения с позицией по опорным маякам — строки «GNSS» и «Расхождение»
- При выходе из режима `beacon_referenced` буфер позиций сбрасывается
- Опорные маяки, выпавшие из маски опроса, не удаляются автоматически — позиция судна «замораживается» на последнем значении (в пределах 20 секунд)

## [1.3.9] - 2026-09-14

### Added
- PWA-оболочка: манифест (`manifest.json`) и Service Worker (`sw.js`) — приложение можно установить как standalone-приложение на десктопе (Chrome, Edge)
- Иконки приложения (192×192, 512×512)

### Changed
- Service Worker регистрируется только в защищённом контексте (http/https). Работа из `file://` и из Android Launcher не затронута
- Автоматическое обновление приложения через Service Worker (`skipWaiting()` + `clients.claim()`) — новая версия применяется при следующем запуске
- Кэширование статики не влияет на работу Web Serial API (serial работает напрямую с USB, минуя сеть)

### Notes
- В standalone-режиме Vivaldi диалог выбора порта Web Serial может не отображаться — это известный баг браузера. В Chrome и Edge standalone работает корректно
